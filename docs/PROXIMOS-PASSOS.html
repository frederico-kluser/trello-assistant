Post-build checklist · Trello Orbit

O que fazer depois que terminar

Brief

O app já está construído: microfone, transcrição pela API STT da OpenAI, análise com o MiMo 2.6 Pro no OpenRouter e integração total com a API REST do Trello (criar, apagar, mover, prazos, etiquetas, comentários, checklists, listas). As credenciais NÃO estão no repositório. Este documento é o caminho exato — em ordem — para você preencher as chaves, ligar seu board real e publicar o app sem vazar nenhum segredo.

01

O que já funciona sem você fazer nada

O app tem modo degradado inteligente: enquanto uma chave não existe, ele usa um substituto honesto e diz isso na tela. Você pode rodar tudo agora, em modo demonstração, e trocar as peças à medida que gera as credenciais.

Sem OPENAI_API_KEY

O microfone continua gravando, mas a transcrição usa o reconhecimento do próprio navegador (Web Speech API). Com a chave, a transcrição passa a ser feita pela API STT da OpenAI (gpt-4o-mini-transcribe por padrão).

Sem OPENROUTER_API_KEY

A análise do que você falou é feita por um interpretador local de comandos em pt-BR. Com a chave, o JEV (typesafe/jev-1.13) passa a decidir em ~0,4 s e o xiaomi/mimo-v2.6-pro assume só quando ele se abstém, com o board inteiro como contexto.

Sem TRELLO_API_KEY

O app roda contra um board de demonstração em memória — nada vai para o Trello. Com key + token + id do board, tudo passa a acontecer no seu board real.

Sem servidor rodando

O projeto foi salvo, não deixei nenhum processo ligado. Para usar: npm install e npm start em server/ (e npm run build em web/ uma vez). Detalhes na fase 1.

02

Onde cada chave entra

Importante: o navegador nunca vê nenhuma chave. Tudo passa pelo servidor (server/), que é o único lugar onde o .env é lido. É por isso que o repositório pode ser público.

Fluxo: você fala → servidor transcreve e planeia → servidor aplica no Trello → o app responde em áudio e anima os cards.
03

As 6 fases, em ordem

Fase 1

Rodar local (5 minutos, sem nenhuma chave)

Instale as dependências, copie o .env.example para .env (pode deixar tudo vazio por enquanto) e suba o servidor. O app já abre em modo demonstração, com um board fictício para você testar a voz e as animações.

terminal 
# 1) dependências
cd server && npm install
cd ../web  && npm install && npm run build

# 2) configuração (pode deixar os valores em branco)
cd .. && cp .env.example .env

# 3) subir — nada fica rodando depois que você dá Ctrl+C
cd server && npm start
# ✦ Trello Orbit · http://localhost:8787
server/package.json web/package.json .env
Fase 2

Trello: key + token + id do board

Esta é a parte manual que você mencionou. A API do Trello existe e é a REST v1 oficial — a key e o token se geram no painel de Power-Ups. Siga o passo a passo clicável logo abaixo desta timeline (detalhe «Gerar as credenciais do Trello»).

Depois de preencher TRELLO_API_KEY, TRELLO_API_TOKEN e TRELLO_BOARD_ID no .env, reinicie o servidor e confira:

terminal — os seus boards, em JSON 
curl "http://localhost:8787/api/trello/boards"
Fase 3

OpenRouter: o JEV decide e o MiMo 2.6 Pro fica de reserva

Gere uma chave em openrouter.ai/keys e coloque em OPENROUTER_API_KEY. O modelo padrão já vem configurado como xiaomi/mimo-v2.6-pro com esforço de raciocínio no máximo (reasoning: {"effort":"max"} — o MiMo pensa o máximo antes de devolver o plano); o servidor manda o board inteiro como contexto e recebe um plano JSON de ações. Se a chave estiver sem saldo, o app cai no interpretador local e avisa na tela — nunca quebra.

OPENROUTER_API_KEY OPENROUTER_MODEL=xiaomi/mimo-v2.6-pro OPENROUTER_REASONING_EFFORT=max
Fase 4

OpenAI: transcrição de voz (quando houver crédito)

Você disse que está sem saldo na OpenAI — sem problema. Enquanto isso, o app transcreve com o reconhecimento do navegador. Quando recarregar, gere a chave em platform.openai.com/api-keys, preencha OPENAI_API_KEY e pronto: o servidor passa a enviar o áudio para /v1/audio/transcriptions.

Modelo de transcrição

O padrão é gpt-4o-mini-transcribe — o mais barato da família e mais que suficiente para comandos curtos. Se preferir o clássico, troque OPENAI_STT_MODEL para whisper-1.

Fase 5

Publicar sem subir credenciais

O repositório pode ficar público: o .env está no .gitignore e o front não recebe nenhuma chave. No provedor de deploy, você apenas preenche as variáveis de ambiente no painel — os valores nunca entram no git.

Importante para o microfone: browsers só liberam getUserMedia em HTTPS (ou em localhost). Em produção, use um provedor que sirva por HTTPS — todos os principais já fazem isso por padrão.

Opção A · Node único

Suba o server/ num Render/Railway/Fly.io/Node e mande o build do web/ junto (o servidor já serve o web/dist automaticamente). Uma URL só, um processo só.

Opção B · estático + API

Front em Vercel/Netlify (build web/) apontando /api para o servidor Node. Nesse caso, ajuste APP_URL e configure CORS no servidor.

Fase 6

Verificação final

Rode o checklist do item 05 neste documento com o board real. Se algo falhar, o painel de voo do app mostra exatamente qual ação falhou e por quê (cada erro da API tem código, mensagem e dica).

04

Passo a passo clicável de cada credencial

Gerar as credenciais do Trello (key + token + id do board)
  1. Abra trello.com/power-ups/admin e entre na sua conta Atlassian/Trello.
  2. Clique em New (ou abra um Power-Up que já exista) e preencha nome à vontade — ex.: Trello Orbit. Ele não precisa de capabilities nem de iframe.
  3. No menu lateral do Power-Up, clique em API Key → Generate a new API key → copie o valor. Isso é o TRELLO_API_KEY.
  4. Logo abaixo da key há um link Token: clique, autorize o acesso com escopo read, write e escolha a expiração (recomendo 30 dias para começar; dá para gerar de novo a qualquer momento). Copie o token: é o TRELLO_API_TOKEN.
  5. Descubra o id do board: abra o board no navegador; no fim da URL há um código tipo /b/AB12CD34. Com a key e o token já no .env, o caminho mais fácil é chamar o próprio app: curl "http://localhost:8787/api/trello/boards" — ele lista id, name e url de cada board. Copie o id para TRELLO_BOARD_ID.
  6. Reinicie o servidor. O cabeçalho do app deve passar de modo demo para Trello.

Escopo mínimo

Este app precisa de read + write nos boards (criar/mover/apagar cards, comentários, checklists). Não precisa de account e não mexe em administração do workspace.

Revogar quando quiser: trello.com/power-ups/admin → API Key → Revoke
Gerar a chave do OpenRouter (serve ao JEV e ao MiMo 2.6 Pro)
  1. Abra openrouter.ai/keys.
  2. Create Key, dê um nome (ex.: trello-orbit) e — recomendado — defina um credit limit para a chave para nunca gastar acima do esperado.
  3. Copie a chave (formato sk-or-v1-…) para OPENROUTER_API_KEY no .env.
  4. Deixe OPENROUTER_MODEL=xiaomi/mimo-v2.6-pro (padrão) ou troque por qualquer outro modelo do catálogo.
  5. Pronto: o servidor já envia os headers de atribuição (HTTP-Referer, X-OpenRouter-Title) e trata 429 com backoff automático.
Gerar a chave da OpenAI (STT) — só quando tiver crédito
  1. Abra platform.openai.com/api-keys.
  2. Create new secret key → copie (formato sk-…) para OPENAI_API_KEY.
  3. Confirme que há saldo em platform.openai.com/usage.
  4. Reinicie o servidor. No cabeçalho do app, STT passa a mostrar gpt-4o-mini-transcribe em vez de navegador.

Enquanto não há crédito

Deixe OPENAI_API_KEY em branco. O app usa o reconhecimento do navegador e mostra um aviso discreto com o caminho para ativar o da OpenAI.

Publicar sem vazar segredos
  1. Confirme que .env está no .gitignore (já está) e que git status não mostra nenhum arquivo de credencial.
  2. No provedor (Render, Railway, Fly.io, VPS…), crie o serviço apontando para server/ com o comando npm start (build do front: cd web && npm install && npm run build).
  3. No painel do provedor, preencha as variáveis de ambiente com os mesmos nomes do .env.example. Elas ficam no provedor, nunca no git.
  4. Confirme HTTPS (obrigatório para o microfone) e teste a partir do celular.
05

Checklist de verificação final

  • Conexão: o cabeçalho mostra STT: gpt-4o-mini-transcribe, JEV: jev-1.13 e MiMo: mimo-v2.6-pro e Board: Trello — sem nenhum selo «modo demo».
  • Criar por voz: fale «cria card testar órbita na lista a fazer» → o app pergunta em áudio, mostra o modal, e só cria após confirmar (com confete).
  • Mover: fale «move testar órbita para fazendo» → o card desliza de anel sem pedir confirmação e o app narra o que fez.
  • Prazo: fale «coloca prazo amanhã no card testar órbita» → o chip de data aparece no card.
  • Apagar: fale «apaga o card testar órbita» → modal destrutivo com botão de segurar para confirmar; o card se dissolve da órbita.
  • Destaque: ao mencionar um card, ele vem para a frente da órbita com a borda iluminada e aparece no painel de voo.
  • Mobile: abra no celular — 3 anéis, cards tocáveis, modal em bottom-sheet, microfone funcionando (HTTPS).
  • Segurança: git log --stat não mostra .env; as chaves continuam só no provedor.
06

Riscos e mitigações

Commitar o .env por engano
HIGH
O .gitignore já bloqueia; se acontecer, revogue as chaves nos três painéis imediatamente e gere novas — nunca tente só "apagar o arquivo" do histórico.
Microfone sem HTTPS em produção
HIGH
Browsers bloqueiam getUserMedia fora de localhost. Sempre publique com TLS (padrão em Render/Railway/Fly/Vercel).
Token Trello com escopo largo ou eterno
MED
Gere com escopo read, write e expiração de 30 dias; renove quando expirar. Revogável a qualquer momento no painel de Power-Ups.
Custo inesperado na OpenAI
MED
Use gpt-4o-mini-transcribe (o padrão) e comandos curtos; sem chave, o fallback do navegador é gratuito.
Operar no board errado
LOW
O TRELLO_BOARD_ID fixa o alvo; o cabeçalho do app sempre mostra qual board está conectado antes de qualquer ação.
Comando de voz interpretado errado
LOW
Criar/apagar sempre passa por confirmação; mover/prazo são reversíveis por voz («move de volta para…») e o card tocado fica em destaque para verificação imediata.
07

Decisões que ficam com você

Onde publicar?

Opção A (um processo Node que já serve o front) é a mais simples e mantém tudo numa URL só. Opção B (estático + API) escala melhor mas exige configurar CORS. Para uso pessoal, A resolve.

Decide with: você · depende de onde já tem conta

Expiração do token do Trello

30 dias é o equilíbrio entre segurança e comodidade; never é mais prático mas só se a chave tiver restrição de escopo e você se lembrar de revogar se algo vazar.

Decide with: você · segurança × conveniência

Idioma e voz das respostas

Está fixado pt-BR (OPENAI_STT_LANGUAGE=pt e voz do navegador em pt-BR). Se quiser inglês/outra voz, é só trocar no .env e no lib/speech.ts.

Decide with: você
